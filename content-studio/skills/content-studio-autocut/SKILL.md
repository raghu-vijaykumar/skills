# Content Studio AutoCut

Run `python <this-skill>/scripts/autocut.py --folder <videos> --duration 12m --style travel-vlog --output <rough-cut>`. Run this after `content-studio-videopreprocess` so AutoCut selects from cleaned, ordered clips; point `--folder` at a flat staging folder of per-clip `final.mp4` exports, because AutoCut scans only the folder's top level. Requires FFmpeg and FFprobe; optionally supply `--transcripts <json>` with per-file timestamped speech segments. The default deterministic heuristic uses scene cuts, audio silence and duration; it does **not** claim to semantically understand landmarks, stories or visual content without externally supplied annotations. Supply `--annotations <json>` for segment relevance scores and descriptive reasons from a vision/LLM analysis stage. Do not fabricate semantics.

Use `--orientation landscape|portrait|square|any` to filter source clips by their measured dimensions before selection. `--include-mismatched` keeps all clips; `--allow <filename>` adds one specific mismatch. `--fit pad|blur|crop|reframe` controls framing for mismatched clips: `blur` (default) centers the clip over a blurred copy of the same footage, `pad` uses black bars, `crop` fills the frame by cropping, and `reframe` (experimental, only when explicitly requested) makes a subject-aware portrait/landscape crop. `--size WxH` sets the target dimensions (default 1920x1080); when size is supplied, its orientation becomes the default target. The decisions file records `orientation`, `size`, `fit`, and `skipped_sources`. The timeline stores `width`, `height`, and `fit`, so later renders use the same treatment.

For a 9:16 portrait deliverable from landscape clips, use the same blurred-background fit as a portrait clip in a landscape edit: `--size 1080x1920 --orientation portrait --include-mismatched --fit blur` (the default). The landscape clip is centered at full width with horizontal blurred bands above and below. Reframing is **experimental**: do not use `--fit reframe` unless the user explicitly asks for a subject-aware crop instead of the blurred bands. When explicitly requested, add `--fit reframe --reframe-mode auto` and optionally `--subjects <json>`. Each selected segment gets a stable reframe crop and a `reframe-preview/shot-XXXX/reframe-review.html` contact sheet. Read [the portrait reframe workflow](references/reframe.md) for the box schema and review rules.

Produces `edit-decisions.json`, `timeline.otio` (OpenTimelineIO JSON schema), `review.html`, and `rough-cut.mp4`. Timeline and decisions are source-referenced and non-destructive. Each selected range carries source in/out timestamps and selection reasons. The review report is a proposal, not publishing approval. Source files are never changed.

For speech-heavy footage, use real timestamped transcript segments to preserve whole utterances; absent transcripts, treat selection as a technical rough assembly requiring manual story review. Export defaults to 1920x1080, 30fps, H.264 SDR and AAC; use `--size WxH` for a different target and `--fit` for mismatched sources. Avoid claiming HDR metadata or Dolby Vision preservation. Use a new output folder, or `--force` to replace generated outputs.

## Mandatory review artifacts and human control

Each render must emit the actual `rough-cut.mp4`, `review/contact-sheet.html`, individual `review/frames/shot-*.jpg`, and `review/audio/shot-*.mp3` for clips with sound, plus `edit-decisions.json`, `timeline.otio` and `review-state.json`. Never replace real evidence with an LLM assertion that it watched or listened to a clip. Review artifacts must refer to the exact selected source time ranges.

Use `python scripts/review.py --output <rough-cut> --request-changes "Shorten intro" --reviewer human` to record feedback, or `--approve --reviewer human` to approve. Approval is a human action and must not be generated by the agent. If changes are requested, the agent should revise the edit plan and regenerate review media before seeking approval again; the current script records feedback but does not yet automatically apply it. Do not publish automatically from a rough-cut output.

Agent workflow: ingest -> analyze -> draft -> render -> generate review media -> request feedback -> revise -> rerender -> request approval -> optionally publish through the existing publishing workflow. At every material checkpoint provide playable audio, video, or representative frames. Keep review rounds bounded and preserve source files. A vision model's scoring is not equivalent to human approval.
