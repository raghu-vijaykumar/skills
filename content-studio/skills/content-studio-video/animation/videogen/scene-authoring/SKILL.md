# content-studio-video-scene-authoring

Before production edits, complete the mandatory `content-studio-workflow` precheck with the exact method, script, outputs, estimate, and review criterion. Use the shared `../runtime/` components and project scene source. For each beat choose a clear representation, frame a hero element alone, and inspect a detail shot before viewing the narrated scene. Review at delivery size; do not claim a new renderer or asset exists without checking.

For Core Explainer video beats, consider the source-neutral [motion primitives](../runtime/components/motion-lab/README.md) when a kinetic headline, chapter path, or layered system view clarifies the mechanism. Compose them with scene-specific visuals; the private reference used to develop them is not a bundled asset.

For a reusable illustrated presenter, use the [2D presenter rig workflow](references/presenter-rig.md). It covers drawing face layers from a reference, saving a local profile, keying gestures and speech to a scene, and checking the rendered result.

For a motion reference, use the shot breakdown in the motion primitives guide. Plan subshot cuts and actor actions at frame precision. Animate the mechanism in separate geometry or rig layers, then prove the state change in a fixed-camera preview before adding camera, typography, or score.

For word-level motion, start from the [full reconstruction checklist](../../../review/critique/references/reconstruction.md). Treat spoken onset, caption emphasis, meaningful object action and presenter reaction as separate cues. Update each cue's clock when narration or cuts change.

When the number of items teaches the idea, build the repeated units separately and hold the wide view long enough to see their organization. Bring one node, group or path forward when its role changes and carry the same identifying cues into the detail shot. Animate the same state used for its label or count. Check the foreground edges in the wide view, the smallest legible label at phone size and the single action that should remain visible when many units move at once.

Run [video critique](../../../review/critique/SKILL.md) on representative narrated renders when a creative reference sets the target. Compare the onset, impact, and settle of each important action. When a retry, handoff, or state change is missing, repair the action before polishing the frame. Choose camera and cut rhythm after seeing the action at speed. Separate word-level text timing and gesture cues from the chapter headline. Verify the top changes using the same mapped beats.

When a reference movement needs to carry over, use the critique skill's [frame trace and object tracks](../../../review/critique/references/frame-tracing.md). Feed verified screen-space displacement into original actors. Give fades, masks, object replacements, and track-loss gaps their own authored actions and retest them in consecutive rendered frames.

For a new idea, use the [frame-indexed Core Explainer route](../references/idea-to-explainer.md). Its reusable `ExplainerFilm` archetypes establish the motion grammar; replace any archetype whose geometry, interface, or action is too generic to explain the actual claim. Preview hero elements alone, then in narrated context, and record native-size rendered evidence.
