# Game asset pipeline review

The original [builder](examples/game_asset_pipeline.py) and [shot specification](examples/game_asset_pipeline.json) show one **bounded crate kit** through UV mapping, packed textures, four LODs, a separate collision proxy, and export preparation. This applies the pinned upstream guidance for [UVs](https://github.com/arjun988/blender-skills/blob/904f095d8f36a6e72adaebb08d07f884a074743d/.claude/skills/uv-workflow/SKILL.md), [textures](https://github.com/arjun988/blender-skills/blob/904f095d8f36a6e72adaebb08d07f884a074743d/.claude/skills/texture-workflow/SKILL.md), [LODs](https://github.com/arjun988/blender-skills/blob/904f095d8f36a6e72adaebb08d07f884a074743d/.claude/skills/lod-pipeline/SKILL.md), [collision](https://github.com/arjun988/blender-skills/blob/904f095d8f36a6e72adaebb08d07f884a074743d/.claude/skills/collision-proxy/SKILL.md), and [export](https://github.com/arjun988/blender-skills/blob/904f095d8f36a6e72adaebb08d07f884a074743d/.claude/skills/export-pipeline/SKILL.md). The gallery shot is a structural and visual example, not a general optimizer or engine-ready asset library.

Both complete Blender 5.3 candidates passed the 72-frame, 960×540, 24 fps shot contract. The exact encoded first, middle, and final frames were inspected. The 480×270 GIFs each decode to 24 frames. The [scorebook](scores.json) records **v1 50/100** (subject 3, motion 1, composition 3, finish 2, evidence 5) and selected **v2 73/100** (4, 3, 4, 3, 5). V1 shows four static, monochrome budgets. V2 adds packed wood and ORM maps, rotating crates, and a cyan collision outline that descends at the end. V2 remains an illustrative asset rather than a photoreal prop; the atlas layout is verified by scene inspection rather than visible in the GIF.

The [saved-scene audit](scripts/audit_game_asset.py) verifies four clean mesh budgets of **264, 120, 72, and 24 triangles** (ratios 1, 0.455, 0.273, 0.091), two material slots per LOD, a 0–1 texture UV and nonoverlapping lightmap UV per mesh, and 90.2% occupancy for the six body atlas cells. It checks packed 256×256 base-color in sRGB and ORM in Non-Color, export copies at origin without animation, and a separate 12-triangle `UCX_` collision box. The mesh checks detect loose vertices and nonmanifold edges. They do not prove automatic LOD selection or physical collision in a game engine. Repeated trim UVs intentionally share atlas cells; there is no high-to-low normal bake. The optimization lane here means a measured triangle/material budget and a declining LOD chain; it does not establish a universal asset optimization pass.

The [export verifier](scripts/verify_asset_export.py) builds an export-only root and LOD hierarchy, adds a 72-frame `AN_Crate_Turn` copy, and selects those objects with the separate collision mesh. Generic, Unity, and Godot use GLB; Unreal uses FBX with animation baking. After clearing source objects and reimporting, each of the four artifacts passed **26/26 Blender round-trip checks (100% technical score)**. The checks cover mesh names and triangles, meter dimensions, two UV channels per LOD, root and LOD parentage, bound wood/metal materials and base-color texture, a 0→0.38→0 radian turn, and the 12-triangle `UCX_` collision mesh without UVs. The GLB cases also verify the imported ORM texture. The animated export copy is a technical handoff probe; it is not an additional gallery candidate.

All three GLB files in this run were byte-identical (`5194a669ef5e578b629342725dcec269ec54ce3e5f343f6fe6bc5fc00391620e`) and their reimported semantic SHA-256 was `061980331e0103f5a7c642fd62b91466692884fd855aa5cc5ea325e95bfaa4ce`. The Unreal FBX reimported semantic SHA-256 was `8a19dec894a0b07daecd573fccc6ea5d46235eb3f7d6f788afb3adece9a8e40e` across two runs; its raw bytes differed because FBX records export metadata. Each JSON report retains its exact raw-file hash. The technical score measures only these Blender checks, not editorial visual quality or engine compatibility. The three named engine adapters remain **Prototype** until Unity, Unreal, and Godot editor imports verify scale, material binding, LOD switching, collision behavior, and the animation clip.

To rebuild from the repository root, render the checked-in v2 spec with the [headless shot command](README.md#rebuild-the-showcases), replacing `<name>` with `game_asset_pipeline`. For the greybox comparison, copy its JSON to ignored `tmp/game_asset_pipeline_v1.json`, set `variant` to `1`, and pass that file as `--input` to the same renderer. Save each MP4 under a separate ignored path and score both before changing the selected GIF. Audit each saved `.blend` with `blender --background --python scripts/audit_game_asset.py -- --blend <blend> --out <report.json>`. For an adapter check, run `blender --background --python scripts/verify_asset_export.py -- --blend <v2.blend> --target generic|unity|unreal|godot --out-dir <ignored-output-dir>`. The winning [GIF](previews/game-asset-pipeline.gif) is embedded inline in the root README; rejected full media and export files remain ignored in `tmp/`.
