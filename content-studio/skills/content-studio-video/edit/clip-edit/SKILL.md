# Clip editing and compatibility engine

Complete the mandatory `content-studio-workflow` precheck before editing. The default camera-footage route hands prepared clips to the user for manual editing. Use this skill only for an explicitly requested trim, cut, join, or review of a supplied render.

The maintained `scripts/content.py` CLI supports `edit trim --input <clip> --start <time> --end <time> --out <new-clip>`, `edit cut --input <clip> --remove <range> --out <new-clip>`, and `edit join` with an approved source order. A join is never the raw-folder default. Keep each output separate from originals and review transitions, color tags, audio, and the full edited export. Read [the edit guide](references/channel-helper.md) for HDR/Dolby Vision and mixed-format constraints.

The existing CLI also contains shared engines used by directly callable [color](../color/SKILL.md), [restoration](../restoration/SKILL.md), [upscale](../upscale/SKILL.md), and [quality](../../review/quality/SKILL.md) skills. Their separate method scripts are the public operation routes; this folder retains the common implementation during extraction. [Source preprocessing](../../source/preprocess/SKILL.md) owns the raw-clip handoff.

When a manual render is supplied, record its hash and analyze actual frames and audio before writing [metadata](references/metadata.md) or requesting a [thumbnail](references/thumbnail.md). Do not invent places, events, speech, or a title from filenames. Vlog transcripts and captions are not generated by default. The approved package and publication remain separate gates.
