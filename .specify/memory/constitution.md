# Skills Constitution

## Core principles

1. **One canonical implementation.** A skill owns its instructions and executable helpers in this repository. Installed copies are generated from a tagged version and are never edited as sources.
2. **Teaching and rendered evidence.** Video tools preserve cue-derived timing, deterministic frames, and the content project's creative rules. Source geometry or passing code checks cannot substitute for rendered review.
3. **Portable interfaces.** Runtime code accepts project paths, composition metadata, themes, and styles as inputs. It must not require Revise Labs paths, branding, or character assets.
4. **Real validation.** A failed gate is a defect. Extraction may parameterize thresholds but must not silently weaken or skip existing applicable checks.
5. **Reproducible releases.** Pin the compatible Remotion family, test a clean Git-tag install, and keep generated media and credentials out of Git.

## Development workflow

Specify the behavior, plan the interfaces, list implementable tasks, then implement and test each independent slice. Review rendered outputs at delivery size where visuals change. Commit and push complete features after reviewing staged files. Preserve unrelated work in consuming repositories.

## Governance

Changes to a public CLI, package export, or content contract require a matching test and documentation update. A release tag is created only after the package and a clean consumer install pass.
